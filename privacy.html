隐私政策

适用范围：部署者本人使用的 Windows BookBot。文档版本：2026-10-18。

1. 访问哪些信息

BookBot 请求 Gmail 的读取权限和发送权限（gmail.readonly、gmail.send）。读取权限在技术上覆盖整个邮箱。程序查询收件箱中标题含 [BOOKBOT]、且晚于配置开始时间的邮件，再核对完整标题、自己发给自己的地址以及已发送和收件箱标签；通过筛选后读取指令正文。

处理内容包括邮箱地址、邮件标识、时间、书名、作者、语言、格式、版本选择和任务编号。程序还处理搜索结果、下载文件、处理状态及错误信息。

2. 怎样使用和传递

  • Gmail 数据仅用于执行本人提交的书籍任务、去重、记录状态和回复结果。
  • 书名、作者等检索条件交给本机配置的电子书工具及其访问的来源；来源也会收到网络请求的正常连接信息。
  • 候选清单、处理结果和符合限制的书籍附件通过 Google Gmail API 发回已配置的同一邮箱。
  • 启用 OneDrive 归档时，相应书籍文件由 OneDrive 客户端同步到本人账户。

本地 BookBot 不调用大模型处理邮箱内容。若用户自行使用聊天助手生成指令，该助手及所连接应用处理的数据适用各自政策。

BookBot 不出售 Gmail 数据，不用于广告、建立用户画像或训练通用人工智能模型。BookBot 对从 Google API 接收的信息的使用和传递遵守 Google API 服务用户数据政策，包括其中的 Limited Use 要求。

3. 保存在哪里、保留多久

OAuth 客户端配置和刷新令牌使用 Windows DPAPI 加密，保存在当前 Windows 用户可访问的本机数据目录。相同用户身份下运行的软件仍可能访问这些数据。电子书工具自己的登录会话由该工具单独管理，不由这份 DPAPI 保护替代。

任务指令、候选结果和状态保存在本地数据库；待发与已发邮件文件、原始下载、书库和日志保存在本地。除日志轮转外，程序没有统一的自动删除期限。候选选择的七天有效期不代表记录会自动删除。Gmail 中的邮件由用户自行管理；OneDrive 的保留及回收机制由微软服务决定。

4. 撤销和删除

  1. 停止 BookBot 后台任务，防止继续处理邮件。
  2. 在 Google 账户的第三方连接页面撤销 BookBot 的授权。
  3. 先保留自己需要的电子书，再删除本机 BookBot 的凭据、数据库、邮件文件、下载和日志。删除本机文件不会自动删除 Gmail 或 OneDrive 的副本。
  4. 按需在 Gmail、OneDrive 和电子书来源账户中处理相应记录或登录会话。

5. 本网站与联系

本网站为静态说明页，不包含统计脚本、广告、表单或邮箱授权功能。部署网站的托管商可能按其政策记录正常的网站访问日志。

本部署由使用者本人管理。如需支持，请联系本部署 Google 授权页面显示的支持邮箱。调整数据用途或部署方式时，应相应更新这份政策。
